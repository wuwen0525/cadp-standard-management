# 中国灾害防御协会团体标准管理系统

面向协会内部使用的团体标准全过程管理系统，覆盖数据看板、项目台账、历史 Excel 台账、15 个流程节点、待补材料、项目档案、办理记录、已发布标准库和标准化体系建设任务。

## 当前能力

- SQLite 统一数据库，刷新页面或更换浏览器后数据不丢失
- 管理员、经办人、专家和只读人员分级使用
- 首次登录强制修改初始密码
- 项目新建、修改、流程推进和审核退回
- 当前环节材料未齐时阻止错误推进
- 项目归档、恢复和分节点文件归档
- 待补材料确认、误报忽略、重新打开
- 真实文件上传、归档和下载
- 所有关键动作自动记录操作人和办理时间
- 项目台账、历史 Excel 台账、待补材料 CSV 导出
- Excel 历史项目、发布记录和年度计划入库，敏感字段按权限隐藏
- 实时数据看板：发布趋势、项目状态、流程分布、材料完整率和年度计划
- 体系建设任务维护
- 数据库与附件每日自动备份，默认保留最近 30 份
- 后端不可用时自动进入本地演示模式

## 本地运行

需要 Node.js 24 或更高版本，不需要安装第三方依赖。

系统目录为 `D:\团体标准管理系统`。在 PowerShell 中运行：

```powershell
Set-Location 'D:\团体标准管理系统'
$env:ADMIN_PASSWORD='请设置一个强密码'
node server.mjs
```

然后访问 <http://127.0.0.1:3000>，账号默认为 `admin`。

未设置 `ADMIN_PASSWORD` 时，本地开发默认密码为 `cadp123456`，首次登录后必须修改；生产环境会拒绝使用默认密码。

数据库、附件、自动备份和 Excel 导入数据默认保存在 `D:\团体标准管理系统\.runtime`，该目录不会提交到 Git：

- `.runtime/cadp.db`
- `.runtime/uploads/`
- `.runtime/backups/`
- `.runtime/imports/`

需要恢复时先停止服务，再用备份中的 `cadp.db` 和 `uploads/` 替换对应运行目录。系统界面只提供备份创建和数据库下载，不自动覆盖当前数据库。

## Docker 部署

```powershell
docker build -t cadp-standard-management .
docker run -d --name cadp-standard-management -p 3000:3000 -e ADMIN_PASSWORD='请设置一个强密码' -v cadp-data:/app/data cadp-standard-management
```

正式部署必须使用 HTTPS，并为 `/app/data` 配置持久化磁盘和定期备份。

## 部署说明

GitHub Pages 只能运行静态页面，不能运行 Node.js 后端或 SQLite。当前 GitHub Pages 可继续作为界面演示；正式数据库版本需要部署到支持 Node.js 和持久化磁盘的服务器、NAS 或云主机，并由该后端同时提供页面和接口。

详细设计见 [docs/系统设计.md](docs/系统设计.md)。

## 数据说明

项目和标准初始数据由现有材料目录整理形成。《科技发展部工作信息 - 团体标准.xlsx》中的 52 条项目记录、21 条发布记录和 7 条 2025 年计划保存在本地数据库，不会提交到公开 GitHub 仓库。待补材料根据文件名称和当前流程环节自动比对，仅用于提示，仍需管理员人工确认。
